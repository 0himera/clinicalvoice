`confidence` шаблонного ответа FSM не превращён в вероятность ASR. Показатель

«да» не авторизует изменение визита, а экстренные слова и просьба о сотруднике
сохраняют приоритет. Три последовательных непонимания переводят на 101.

## Задержки

CPU, последовательный справочный запрос. Локальная машина: 12 логических CPU;
ВМ: 4 CPU. На каждой исключён один прогрев, учтены пять повторов. Значения —
миллисекунды. Для пяти наблюдений p95 по nearest rank совпадает с максимумом.

| Фаза | Локально p50 / p95 | ВМ p50 / p95 |
| --- | --- | --- |
| TTS контрольной входной фразы | 32,70 / 772,93 | 41,03 / 1167,65 |
| ASR | 1161,50 / 1218,83 | 1043,09 / 1053,46 |
| HTTP-шаг контроллера | 2,42 / 3,16 | 2,76 / 3,22 |
| Последовательная сумма фаз | 1210,17 / 1994,38 | 1084,65 / 2222,09 |

Это синтез тестовой фразы → ASR → HTTP-ответ. Проигрывание, SIP/RTP, паузы
пациента и синтез ответа бота в эти числа не включены. Резервный NLU в этом
benchmark выключен; измеряется детерминированная справка. Это не проверка
конкурентных звонков, нагрузочной ёмкости или бизнес-KPI. Аудио не сохраняется.

## Проверки

- `make check build`: Go race/vet/gofmt, Ruff, 51 Python-тест локально и на ВМ.
- Регрессионный датасет через HTTP: 51/51 локально с THX-01/Ollama и 51/51 на ВМ с THX-01/разрешённым `hub`; визиты проверяются после каждого шага.
- Повторён весь CSV zer0days: 29 PASS, 4 PARTIAL, 2 BLOCKED, 1 CONFLICT, 0 FAIL в HTTP/mock-контуре; критические — 5/5. Внешняя МИС и SIP не засчитываются по этому mock-прогону. Первичный результат — `var/zer0days-polish-20261020/`.
- Голосовые TTS → ASR → HTTP на ВМ: один вымышленный визит создан, перенесён с сохранением ID и отменён в отдельной mock-базе.
- Входящий SIP на ВМ: после согласия создан и затем отменён именно свой визит. Полная запись заняла 73,07 секунды; пациент синтетический, человеческих пауз нет. Это один замер при ориентире 150 секунд.
- Все три исходящих SIP-сценария прошли: подтверждение, перенос того же ID и отмена. Фактические SIP-переводы на 101, 104 и 102 также прошли.
- После проверок удалён временный mock override, рабочее ядро снова готово в режиме `stand`. Приватный `.env` и рабочая БД сохранены; новые операции внешней МИС в этом прогоне не выполнялись.

В регрессионном TC-04 устранена календарная зависимость от постоянного 08:20:
сценарий ограничен одним врачом и называет фактически предложенное время.
Ожидание осталось прежним — выбор временем без номера, отдельное согласие,
проверка фактического времени созданного визита. Ожидания исходного CSV zer0days
не менялись; его ограничения и конфликт переноса описаны в предыдущей приёмке.

## Повторение

Из корня, после обычной установки проекта и запуска речевого сервиса:

```bash
make check
make config-check
AI_WORKER_URL=http://127.0.0.1:8000 make benchmark
make scenarios
```

Для отдельного диагностического worker на 18000 задайте соответствующий
`AI_WORKER_URL`. `ai-worker/.venv/bin/python scripts/benchmark_voice.py --samples 10 --output var/my-benchmark.json`
позволяет увеличить число повторов; существующий файл не перезаписывается.
Статическая проверка конфигурации не заменяет `/readyz`, готовность весов и
проверку содержимого Excel. Она не обращается в МИС и не загружает модели.
