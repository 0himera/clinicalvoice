# Приёмка и уточнения кейса

Источники: `data/task.txt`, `data/reglament.txt`, переписка организаторов 14–15 октября 2026 года из предоставленного пользователем `dbi.txt` и [OpenAPI стенда](https://crm-med-mock.dbi-testing.ru/docs/openapi.json). Последняя строка переписки обрывается; неизвестные ответы не домысливались.

## Уточнения организаторов

| Вопрос | Принятое условие |
| --- | --- |
| Демонстрация звонка | SIP-софтфон с АТС подходит; браузерный микрофон недостаточен; реальный телефонный номер избыточен |
| Расписание | Excel выдан отдельно; сопоставление по уникальным ФИО и специальности, без Excel-ID в API |
| Экстренная заявка без идентификации | Допускается технический клиент; предварительная идентификация также разрешена, но проект не задерживает предупреждение |
| Вызов врача на дом | Заявка специалисту с адресом и причиной в свободном тексте |
| Анализы | Нормативный срок из таблицы регламента и способы получения; API лабораторных статусов не требуется |
| Исходящий обзвон | Живой исходящий звонок с подтверждением, переносом и отменой; подтверждение комментарием клиента |
| Задержка ответа | Отдельного обязательного норматива нет; показатели ожидания линии остаются целями пилота |
| Оплата | Вне обязательного объёма кейса |

## Матрица проверок

| Проверка | Уровень и критерий |
| --- | --- |
| Запись | Go/API и голосовой smoke: ровно один новый визит после явного согласия |
| Перенос | Тот же ID, новое время или врач, прежний слот доступен |
| Отмена | Статус МИС изменён, локальный слот свободен; ошибка МИС не озвучивается как успех |
| Неопределённое подтверждение | «Повторите время» не создаёт визит |
| Уточнение шага | Повторные «зачем?» объясняют цель запроса, сохраняют поля и не приводят к R-05 |
| Справка посреди записи | Ответ об адресе/документах и возврат к текущему вопросу; выбранный слот сохраняется |
| Согласие внутри вопроса | «Да, зачем подтверждать?», «да, если успею», «буду занят» не создают визит |
| Выбор врача по жалобе | Утверждённый сценарий первичного приёма с отдельным согласием; для ребёнка проверяется представитель |
| Несколько задач | Уточняется первая задача, ни одна не выполняется без собственного подтверждения |
| Отрицания | «Не подходит», «не смогу», «да, не отменяйте» не становятся согласием |
| Идентификация | Кириллица, даты словами и явно названные год/месяц/день; невозможные даты отвергаются; уточняются только недостающие поля |
| Уточнение расписания | «Хочу узнать расписание» → вопрос о враче; ответ специальностью или «поликлиники» продолжает сценарий без ложного непонимания |
| Часы работы | «В какие дни вы работаете?» и другие разговорные формулировки получают ответ по регламенту; вопрос о конкретном враче обращается к его расписанию |
| Резервный NLU | Сложная реплика → проверенный JSON → сценарий; справочник и справочные ответы из исходных данных; ошибка провайдера → уточнение; модель не подтверждает операции |
| Красный флаг | Прерывает все рабочие состояния; предупреждение 103/112 и внутренний маршрут 104 |
| Человек | Доступен в середине любого сценария |
| Непонимание | После третьей последовательной неудачи — перевод; счётчик не сбрасывается пустым успехом |
| МИС | Пагинация, кэш, лимитер, 429, отмена контекста, терминальные статусы и сохранение mock после рестарта |
| Конкуренция | Одна победившая блокировка слота; параллельные HTTP-реплики не вызывают гонок |
| Повтор HTTP | Повторный turn_id воспроизводит прежний результат без второй операции |
| Заявки | Неизвестный пациент → техническая карточка; неизвестный исход POST не повторяется |
| Телефония | Живой SIP/RTP smoke, плюс независимые тесты AudioSocket, VAD, PCM, AMI |
| Напоминания | Согласие, GMT+4, окно обзвона, пятница/понедельник, отсутствие повторов подтверждённого визита |
| Синтез | Голос запроса учитывается, даты/время произносятся словами, телефонное аудио 8 кГц |
| Короткие ответы | «Да», «нет», «зачем» после других реплик и длинной тишины доходят до ASR; проверяются разные смещения относительно VAD-кадров |

`make check` запускает проверки без моделей. Голосовые и SIP-проверки запускаются отдельно, с реальными моделями и изолированной mock-базой. Они не считаются проверкой внешнего стенда без токена.

## Выполненная локальная проверка

На локальном стенде с Excel организаторов проверены:

- `make check`: Go-тесты с `-race`, `go vet`, Ruff и Python-тесты, включая отключение отладки по умолчанию, закрытые файлы и трассировку AudioSocket.
- Python-тесты в отдельном чистом окружении без PyTorch и загрузки моделей.
- Настоящие TTS → ASR → HTTP-сценарии записи, переноса того же визита и отмены.
- Входящий SIP/RTP-звонок через Asterisk с записью и отменой.
- Три исходящих SIP-звонка: подтверждение с проверкой комментария карточки, перенос с сохранением ID и отмена.
- SIP-перевод на зарегистрированного оператора 101 и экстренный внутренний маршрут 104.
- Офлайн-запуск речевого сервиса с предварительно загруженными локальными моделями.
- После явного подключения Gemini проверен настоящий SIP-звонок: синтезированная сложная реплика → локальный ASR → Gemini API → каталог из Excel → локальный TTS. В трассе подтверждены `llm_used=true` и `DIRECTORY_INFO`.
- Сложный диалог из 23 реплик проверен текстом и через настоящие локальные TTS/ASR с Gemini: повторные «зачем?», неполная идентификация, справка при подтверждении, запись, перенос того же ID и отмена. После каждой реплики проверяются записи mock-МИС.
- Матрица из 48 случаев с настоящим Silero VAD, G.711, паузами и смещениями кадров проверяет сохранение коротких ответов после сброса рекуррентного состояния.
- Через Asterisk выполнен SIP-звонок из семи реплик с синтетической речью: повтор приветствия, каталог через Gemini, выбор первичного приёма, короткое «да», «зачем?», повтор и завершение. Все переходы сверены с трассой; счётчик ошибок оставался нулевым, визиты МИС не изменились.
- С токеном команды проверен внешний API стенда: авторизация, сопоставление всех 85 врачей с Excel, создание вымышленного пациента, запись после явного согласия, перенос того же visit ID и отмена после отдельного подтверждения. Проверены статус «Отменена» в МИС и освобождение локальной блокировки слота. Для стенда использована отдельная база; текстовая трассировка и обход часов обзвона выключены.

При внешней проверке один контрольный GET списка визитов вернул через локальный API ошибку 502. Последующие чтения отдельного визита и списка подтвердили выполненный перенос; изменение повторно не отправлялось. Причина исходной ошибки чтения не установлена. Отмена затем проверена отдельным диалогом с тем же вымышленным пациентом.

Голосовые и SIP-прогоны выполнялись с mock-МИС; внешняя МИС проверена через HTTP-диалог. Во всех проверках использованы вымышленные пациенты. Метрики бизнес-эффекта и нагрузочные характеристики эти проверки не измеряют.
