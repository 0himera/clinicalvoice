# Локальный API

На ВМ хакатона API доступен на loopback; подключение, сервисы и SIP-шлюз
описаны в [инструкции развёртывания](deployment.md). `make health` проверяет
готовность ядра и локальных речевых моделей без вывода токенов.

NLU-шлюз организаторов: `LLM_PROVIDER=hub`,
`LLM_BASE_URL=https://hub.gigaschool.ru/api/v1/llm/v1`, приватный `LLM_API_KEY`
и явное `LLM_ALLOW_REMOTE=true`. Через него проходит только текущая допустимая
реплика и состояние; закрытый словарь применяется и к этому провайдеру.

Ядро: `http://127.0.0.1:8080`. Все тела — JSON UTF-8. Всегда нужен непустой `CORE_API_TOKEN` и `Authorization: Bearer …`; `/healthz` открыт для проверки процесса. Токен генерируется `make setup`. В документацию и журналы его не копируют.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/healthz`, `/readyz` | Liveness (`/healthz`, `/health`) читает SQLite; `/readyz` проверяет также пул записи. Все health-маршруты открыты |
| POST | `/api/dialogue/start` | `{caller_number?, channel_id?, outbound_visit_id?}` → 201, call_id и приветствие |
| POST | `/api/dialogue/turn` | `{call_id, text, turn_id?}` → ответ, state, scenario, outcome |
| POST | `/api/dialogue/{id}/end` | Закрыть сессию и освободить временный слот |
| POST | `/api/dialogue/{id}/transfer` | Выполнить ранее назначенный контроллером перевод через AMI |
| POST | `/api/dialogue/{id}/interrupt` | `{text}`; независимая проверка безопасности и прерывание ожидания МИС |
| GET | `/api/doctors` | Локальный кэш сопоставленного справочника |
| GET | `/api/visits` | Визиты команды для диагностики; на реальном стенде расходует квоту |
| GET | `/api/clients/{id}` | Карточка клиента, в том числе подтверждение в комментарии; доступ защищён общим токеном |
| PUT | `/api/contacts/{client_id}` | `{endpoint: "PJSIP/200", reminder_consent: true}` |
| POST | `/api/reminders/dial` | `{visit_id}`; требует согласия, контакта и разрешённого времени |
| GET | `/api/stats` | Измеренные локальные исходы и число сохранённых сессий |
| GET | `/api/escalations` | Число заявок по статусам |
| GET | `/api/escalations/review` | ID, статус, MIS ID и попытки проблемных заявок без текста пациента |
| GET | `/api/slot-claims` | Pending/uncertain слоты: врач, время, visit ID, call ID |
| POST | `/api/slot-claims/reconcile` | Читает визиты МИС и сверяет uncertain; несовпавшие слоты остаются заблокированы |

Для надёжного повтора реплики клиент генерирует UUID `turn_id` до запроса. Один ID нельзя использовать для другого текста. 409 также означает одновременный запрос одной сессии. Истёкшая или неизвестная сессия даёт 404 и не создаётся заново автоматически. Метод GET не открывает звонок. Новая реплика закрытого звонка даёт 410; точный повтор сохранённого turn ID воспроизводит результат. До 256 новых шагов на звонок; затем 429. Результаты не вытесняются из кэша до удаления сессии. После перезапуска сессии не восстанавливаются: старый call ID получает 404 и не выполняет операцию повторно.

Прерывание безопасности имеет приоритет над обычным ответом и его кэшем. Телефонный адаптер проверяет распознанную реплику через `/interrupt`, даже если предыдущая операция ещё выполняется. Контекст обычного шага отменяется, но МИС могла уже выполнить подтверждённое изменение; полученный результат фиксируется отдельно от реплики о переводе. Повторной отправки неизвестной операции нет. Сохранение заявки и освобождение временного hold выполняются отдельно с ограниченным временем: ответ прерывания может иметь `escalation_queued=false`, пока запись ещё идёт. Это не обещание доставки.

`should_hangup` и `transfer_target` — команды телефонному адаптеру. Клиент сначала воспроизводит речь, затем завершает или переводит вызов. Сам API не выдаёт факт отправленной SMS и не присваивает визитам неподдерживаемые статусы.

R-09 переводит острую зубную боль/отёк на `102`. Просьба «соедините» — на `101`, угроза жизни — на `104`. При ненайденной карточке запрашивается повторная проверка данных, затем R-07/101; автоматической регистрации нет. Индивидуальная готовность анализов недоступна: R-08/101 без выдуманного результата.

Безопасный GET к МИС после 429 повторяется не более одного раза с учётом Retry-After и контекста. POST/PATCH не повторяются. Если диагностическое чтение не уложилось в квоту, API возвращает 503 и заголовок Retry-After; обычный `/turn` сообщает о переводе для проверки результата. Прямой повтор клиентом мутации с неизвестным результатом не допускается.

Речевой API: `http://127.0.0.1:8000`, обязательный непустой токен `AI_API_TOKEN`, аналогичный Bearer-заголовок. `/health` открыт. `POST /asr`: multipart-поле `file` с WAV. `POST /tts`: `{text, speaker?, sample_rate?}` → WAV. Поддерживаемые частоты: 8000/16000/24000/48000. Ошибки не возвращают пустой WAV с кодом 200. `POST /v1/decide` (и `/decide`): `{state, questions}` → `{model: "THX-01", answers: {...}, latency_ms: float}` (явный mock возвращает `model: "mock"`); неавторегрессионная классификация типизированных вопросов (choice, noul, excerpt) через mmBERT в изолированном потоке без генерации токенов. Эндпоинт защищён Bearer-токеном и доступен строго по локальному интерфейсу.

Ответ диалога может содержать `reason_code` — код регламентной причины перевода, например `R-05` после трёх непониманий. Необязательные `DEBUG_DIALOGUE=true` и `DEBUG_LOG_DIR=var/debug` включают локальные текстовые трассы для mock-режима; по умолчанию трассировка отключена. Оба сервиса нужно перезапустить после изменения этих настроек.

Технические события пишутся в `TECHNICAL_LOG_DIR` без текста пациента и параметров поиска МИС. Отдельный opt-in `TRANSCRIPT_LOGGING=true` включает зашифрованные тексты ASR, ответы бота и JSON NLU, включая стенд МИС. Нужен отдельный локальный ключ `TRANSCRIPT_KEY_PATH`, срок `TRANSCRIPT_RETENTION_HOURS` ограничен 24 часами. Стенограммы не выдаются через HTTP API: их читает только локальная утилита `go-core/bin/transcripts`. Аудио не сохраняется. Поля диагностики выбора слота остаются внутри технического журнала и не являются командами клиента.

`llm_used` показывает применение резервного NLU на этой реплике. Локальная Ollama включается через `LLM_PROVIDER=ollama`; модель по умолчанию — `gemma4:e4b`, рассуждения отключены через `reasoning_effort=none`. Gemini включается явно: `LLM_PROVIDER=gemini`, `LLM_ALLOW_REMOTE=true`, `LLM_API_KEY` (или `GEMINI_API_KEY`); по умолчанию используется `gemini-3.5-flash-lite`. Таймаут задаётся `LLM_TIMEOUT_SEC`, бюджет JSON — `LLM_MAX_TOKENS` (по умолчанию 256). Ответ с `finish_reason=length` не применяется. В отладочном логе ядра есть `nlu_attempted`, `nlu_intent`, `nlu_latency_ms`, `nlu_error`. Ответ модели не является командой на запись или отмену; подтверждения не передаются LLM. `STATE_DIRECTORY` перечисляет врачей и профили из действующего справочника, «дальше» показывает следующую страницу.

Уточнение «зачем?» и просьба повторить сохраняют состояние и не считаются ошибкой распознавания. Справочный ответ в рабочем состоянии возвращает пациента к незавершённому вопросу. Вопрос о выборе врача сначала переходит в `STATE_OFFER_BOOKING`; данные пациента запрашиваются после согласия. Слова согласия внутри вопроса или условия не авторизуют изменения.

Все переменные и значения по умолчанию перечислены в `.env.example`. Адреса HTTP-сервисов и TCP-телефонии по умолчанию локальные. Выход за loopback требует длинного API-токена и отдельной сетевой конфигурации. `SCHEDULE_PATH` обязателен, если в `data/` нет ровно одного Excel. `MIS_API_TOKEN` включает внешний стенд, пустое значение — долговечный локальный mock. `DATABASE_PATH` разделяет рабочие и диагностические данные.


Удалённый NLU проверяет закрытый словарь до HTTP во всех состояниях. Данные пациента, числа, словесные даты, адреса и неизвестные слова требуют локального разбора; удалённая модель не извлекает идентификацию пациента. Локальные модели работают с исходной текущей репликой. Отмена HTTP-запроса не является остановкой native-инференса; ёмкость остаётся занятой до его завершения.

Reconciliation — чтение, не повтор POST. Пустой снимок МИС не доказывает, что неизвестное изменение не выполнилось. Не найденные uncertain требуют проверки сотрудником в стенде. Для заявок сопоставляется UUID `Обращение …` в описании МИС; автоматической повторной отправки нет. `source`, `intent`, `explanation` — технические метаданные; `confidence` шаблона не является измеренной вероятностью клинической правильности.
