# Речевой сервис

FastAPI предоставляет локальные `/health`, `/asr` и `/tts`. При включённой телефонии тот же процесс слушает FastAGI на 127.0.0.1:4573 и AudioSocket на 127.0.0.1:9092. Рабочие модели: Faster-Whisper small, Silero TTS v4_ru и Silero VAD ONNX. У каждого звонка отдельное состояние VAD; после 640 мс тишины оно сбрасывается для обнаружения коротких ответов после пауз. Доступ к ASR и TTS ограничен и сериализован отдельно для каждой модели.

Из корня проекта:

```bash
make install
make run-ai
make test-python
```

Тесты используют внедряемые модели и не требуют CUDA или загрузки весов. `make install` устанавливает дополнительную группу `models`; обычный CI устанавливает только зависимости для HTTP и тестов. `DEVICE=cpu` явно выбирает CPU, `DEVICE=cuda` требует доступной CUDA, `DEVICE=auto` определяет устройство автоматически.

`POST /asr` принимает WAV, не более 4 МиБ и 30 секунд, mono/stereo, 8–96 кГц. Аудио приводится к 16 кГц. `POST /tts` принимает `text`, необязательные `speaker` и `sample_rate` (8000, 16000, 24000 или 48000); для телефонии используется PCM16 mono 8 кГц. Голос запроса учитывается.

`AI_API_TOKEN` защищает HTTP API; `/health` доступен без токена. CORS не открыт. Аудио не сохраняется. По умолчанию текст пациента не пишется в журнал; явно включённый `DEBUG_DIALOGUE=true` сохраняет распознанные реплики и ответы в закрытые локальные JSONL-файлы и разрешён только с mock-МИС. После изменения настроек перезапустите процесс. На неготовых моделях процесс не объявляет успешную готовность. Отмена запроса не освобождает вычислительный слот до фактического завершения потока инференса.
